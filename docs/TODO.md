> 이 문서는 **구현 또는 필요한 검증이 남은 작업**만 담는다.
> 끝낸 항목은 여기서 지우고, 결과는 `MASTER_PLAN.md`「구현 완료 단계」에 한 단계로 적는다.
> 단계 배경과 아키텍처 원칙은 `MASTER_PLAN.md`, 코딩 규칙은 `DEVELOPMENT_GUIDE.md`.
>
> **「즉시」 판정 항목(3개 파일 이상 중복, 1,000줄 초과)은 여기에 넣지 않는다** —
> 발견한 작업 안에서 처리한다.
>
> 각 활성 작업 ID의 검증 게이트와 증거는 `VERIFICATION.md`의 작업별 체크 매트릭스에서
> 관리한다. TODO 항목을 완료 처리하기 전에 해당 행의 적용 게이트를 모두 체크하고,
> 작업 성격상 불필요한 게이트만 `N/A`로 기록한다. 필요한 OS 확인을 못 한 경우는
> 대기 또는 `USER_ACCEPTED`로 구분하고, 미수행을 해당 없음으로 지우지 않는다.

각 항목은 **한 턴/한 커밋 단위로 끝낼 수 있는 크기**로 쪼개 두었다.
`선행` 표시가 있으면 그 항목을 먼저 끝내야 한다.

모든 항목은 고유 ID와 진행률을 가진다. 체크박스는 완료 여부, 진행률은 실제 구현·테스트·
검증 증거에 따른 현재 상태를 뜻한다. 완료한 항목은 이 문서에서 제거하고 `MASTER_PLAN.md`에
완료 이력을 남긴다.

> **검증 절차는 여기 복제하지 않는다.** 표면별 절차와 판정 기준은
> `DEVELOPMENT_GUIDE.md`의 「실행 표면 하드 게이트」와
> 「GPUI 시각 검증 및 독립 크로스체크」가 정본이고, UI를 바꾼 작업마다 그 자리에서
> 수행한다. 여기에는 작업별로 꼭 필요한 잔여 수용 조건만 한 줄로 남긴다.

## 0. VirtualBox 오프라인 디스크 탐색·복사 — Phase O

### 범위와 안전 계약

초기 릴리즈는 **종료된 VM의 VDI를 읽기 전용으로 탐색**하는 것만 지원한다. 원본 VDI에는
어떤 쓰기도 하지 않으며, 실행 중 VM의 VDI 직접 읽기와 Guest Control 파일 접근은 모두
지원하지 않는다. 결정 정본은 `VIRTUAL_DISK_BACKENDS.md`다.

현재 판단: Windows 게스트의 NTFS를 1차 파일시스템으로 지원하고, Linux 게스트의 ext4는
오프라인 백엔드가 안정화된 뒤 추가한다. 이 선택은 이번 기능의 필수 경로를 먼저 작게
검증하기 위한 것이며, `GuestFileSource` 추상화로 후속 백엔드를 막지 않는다.

### O-3. 파일 복사 안전성

오류 억제·재표시 `VDE-012`는 기존 GPUI 클릭·저장 검증과 릴리즈 오류 표시 증거로 완료했다.
검증 기록은 `VERIFICATION.md`를 참조한다.

### O-4. GPUI 탐색기

  외부 입력 도구 미지원만으로 다시 대기열에 올리지 않는다.
- `E-001`~`E-004`: 신규 기능은 구현 전에 개인정보·권한·전역 동작 범위를 확정해야 한다.
  클립보드 히스토리는 기본 비활성·로컬 보관·텍스트/이미지 보관 한도와 민감정보 제외 정책,
  프로세스 모니터는 강제 종료 권한과 보호 프로세스 정책, 빠른 실행기는 전역 단축키 등록과
  실행 대상 신뢰 범위, 스크린샷 도구는 화면 캡처 범위·클립보드 전송·파일 보관 정책이 필요하다.
  이 결정 전에는 백그라운드 수집이나 강제 종료 동작을 구현하지 않는다.
- `K-001`~`K-005`: macOS 실행 환경·메뉴 막대·`launchd`·`.icns` 패키징 및 Apple Developer
  계정 확보 여부 확인이 필요하다. 현재 Windows 검증 환경에서는 구현·검증하지 않는다.
- 전체 `cargo fmt --check`: 기존 baseline의 다수 포맷 불일치가 있어 이번 테스트 커밋에서는
  전체 재포맷을 수행하지 않았다. 다음 별도 구조/정리 작업에서 범위를 결정한다.
